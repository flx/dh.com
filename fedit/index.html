FEdit

A lightweight, memory-frugal text editor for macOS.

Editing a couple of kB of text should not cost a gigabyte of RAM. FEdit deliberately avoids heavyweight machinery: native AppKit text views instead of a web-based editor, and a native Markdown renderer instead of an embedded browser. In practice it settles at roughly 80–190 MB with small files open — the point is the order of magnitude, not a race to the bottom.

Platform: macOS 26 or later Swift, SwiftUI and AppKit No third-party dependencies GPL-3.0-or-later
View source on GitHub Read the README Report an issue

There is no App Store build and no signed download: FEdit is source you build yourself, in Xcode or with the one-line installer below.

What you can do

Three columns, one window

  • Folder sidebar, editor, and a Markdown preview that appears only for Markdown files.
  • Draggable, persisted splits, each column under a fixed header strip.
  • Windows are independent: own folders, filter, open file, and cursor.

A sidebar that survives big folders

  • Open several top-level folders at once, each its own section.
  • Filter with a small boolean query language: .py OR .swift.
  • Scanning runs off the main thread, so the window stays usable while a large root fills in.
  • Files that differ from HEAD get a read-only “(changed)” badge in a git repo.

Editor, with the essentials only

  • Line numbers, soft wrapping, and font size zoom that persists.
  • Lightweight syntax highlighting for Swift, Python, and Markdown.
  • Opens any UTF-8 text file, with a Latin-1 fallback.

Find that stays out of the way

  • ⌘F opens a find bar over the editor text, never the preview.
  • Literal matching with a visible Case sensitive checkbox, off by default.
  • Every match highlighted, a 3 of 17 count, and wrap-around stepping.
  • In a narrow column the bar wraps to a second row rather than spilling over the dividers.

Markdown, rendered natively

  • No WKWebView: the preview is a real text stack, not a browser.
  • GFM pipe tables become properly aligned grids, with a bold header row.
  • The preview follows the first line visible in the editor.

Saving you never think about

  • Autosave is unconditional and always on — no toggle, no “Save changes?” dialog.
  • Writes on a typing pause, on file switch, and on window close or quit.
  • A clean buffer reloads when the file changes underneath you; a dirty one is kept.
  • Sessions restore folders, last file, cursor position, splits, and windows.

Light appearance only, deliberately — no dark mode and no themes. Tabs, split editors, and search-and-replace are non-goals too.

Keyboard

⌘N New… — create a file in the open file’s folder
⌘O Open Folder… — opens a new window and prompts for its root
⇧⌘O Add Folder to Window…
⌘S Save (autosave is always on regardless)
⌘F Find — open the find bar over the editor text
⌘G / ⇧⌘G Find Next / Find Previous, wrapping at either end
⌘+ / ⌘− / ⌘0 Increase, decrease, or reset the editor font size

Install and build

There are no third-party dependencies, so a clone and a build is the whole story. The installer builds the Release configuration, installs FEdit.app into /Applications, and drops a fedit command on your PATH. It never uses sudo. 

git clone https://github.com/flx/FEdit.git
cd FEdit
scripts/install.sh

Or open FEdit.xcodeproj in Xcode 26 and hit Run. Building needs macOS 26 and Xcode 26.

From the command line

Each path opens in its own new window, and a file’s containing folder becomes that window’s sidebar root. Existing windows are never disturbed. 

fedit notes.md            # one file, folder as root
fedit .                   # the current directory
fedit src/a.py docs/b.md  # one window each
fedit --wait notes.md     # block until it closes

Because --wait blocks until the window closes, FEdit works as your git editor: 

git config --global core.editor "fedit --wait"

FEdit autosaves, so there is no “close without saving”. To abort a commit, delete the whole message text and then close the window — git sees an empty message and stops.
