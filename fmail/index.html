FMail

A menu-bar companion for Apple Mail.

Apple Mail keeps your mail; FMail fixes what is awkward about getting at it. It lives entirely in the menu bar — no window, no Dock icon — reads Mail’s on-disk store read-only, and mirrors the metadata into its own SQLite + FTS5 index. Click the envelope and you get an unread count that matches reality, a search box that takes a real query language, and a list split so the reply you are waiting on sits above the newsletters. Reading and replying stay in Mail.app.

Platform: macOS 14 or later Swift 6, AppKit and SwiftUI Menu bar only — no window, no Dock icon GPL-3.0-or-later
View source on GitHub Read the README Report an issue

There is no App Store build and no signed download — GPL-3.0 is incompatible with App Store distribution. FMail is source you build yourself, in Xcode or from the command line.

What you can do

A dropdown instead of a window

  • Your unread mail, newest first, under Today / Yesterday / date separators.
  • Up to 15 rows per block, each with an unread dot and a checkbox.
  • The menu-bar icon carries the global unread count as a badge.

Real replies above the noise

  • The list splits into Priority Messages and Other Messages.
  • Anyone you have emailed counts as priority, derived from your sent mail automatically.
  • A supplemental list covers senders you only ever receive from: a full address, a bare word or domain, or a * / ? wildcard.
  • Add or remove a sender straight from that message’s submenu.

Mark read without leaving the menu

  • Per-block Mark displayed … as read / as unread commands.
  • Tick a few rows and they collapse to Mark N as read / as unread.
  • A command that would change nothing is greyed out rather than quietly doing nothing.

Search that composes

  • AND, OR, NOT, parentheses, and quoted phrases.
  • Field operators for sender, recipient, subject, body, attachment, account, mailbox, flags and dates.
  • Attachment queries by family and size: attachment-type:pdf attachment-size:>1mb.
  • Results replace the list and stay split into Priority and Other.

Reading and replying stay in Mail.app

  • Open in Mail hands the message off; FMail never renders a body itself.
  • Reply, Reply All and Forward drive Mail’s own AppleScript, so the familiar compose window opens with the original properly quoted.
  • No SMTP, no sync layer, no cloud — nothing is ever sent by FMail.

An index that keeps up

  • Mirrors Apple’s Envelope Index on launch, then incrementally via file-system events plus a 60-second safety net.
  • Opening the menu runs a fast read/unread reconcile, so what you did in Mail.app is already reflected.
  • Bodies fill in on a background sweep of the .emlx files: new mail is findable by subject, sender and attachment name at once, by body text shortly after.

Menu-bar only, deliberately. FMail started as a three-pane window app with in-app HTML rendering; that UI was removed rather than maintained. Rendering message bodies and composing mail are non-goals — Mail.app already does both, and better.

Why it exists

Drifting unread counts Mail’s badge and its actual unread set disagree. FMail recomputes the count from the Envelope Index every time you open the menu, and shows you the messages it counted.
Weak search No real boolean operators, awkward dates, no way to scope by topic, time and person at once. FMail’s search box takes a structured query language instead.
Real replies buried under noise A busy unread list mixes the answer you are waiting on with receipts and newsletters. The Priority / Other split puts correspondence first.

Search syntax

Adjacent terms are AND-ed, and everything composes freely with AND, OR, NOT (or a - prefix), parentheses and quoted phrases. Unquoted terms match by prefix, so subject:v finds vermont.

from: to: cc: Sender or recipient, address or display name. Domain-style works: from:vendor.com.
subject: body: One field only, rather than everything at once.
attachment: attachment-type: attachment-size: Filename, family (pdf, word, image, archive, …), or byte size with a comparator and unit.
account: in: Scope to one account, or to a mailbox kind: inbox, sent, archive, trash, junk, all.
is: has: is:unread, is:read, is:flagged, has:attachment.
before: after: on: ISO dates, month names, or relative forms: 7d, 2w, "last 30 days".
thread: Scope to a single conversation — useful with body: to grep inside a thread. 
from:alice subject:invoice
"exact phrase" -draft
(from:alice OR from:bob) is:unread
account:gmail.com (subject:invoice OR subject:receipt) after:2024
in:sent has:attachment after:"last 30 days"
from:bank attachment-type:pdf attachment-size:>1mb

An optional MCP server

FMail ships a read-only MCP (Model Context Protocol) server, so an LLM client — Claude Code on the same Mac, or a claude.ai connector — can search the index, read threads, pull attachments to disk and export a conversation to Markdown. Twelve tools, none of them destructive: mail state only ever changes through Mail.app.

It listens on 127.0.0.1 and is gated by a bearer token, or by an OAuth session you approve in a time-limited window. A Cloudflare tunnel can put it on a public hostname for remote access, but only ever when you click to open it — and if a tunnel is configured without a credential the server fails closed and refuses every request.

Attachment bytes are attacker-controlled by definition — anyone can email you a file. Writes requested over a tunnel are therefore confined to iCloud Drive/FMail, with .. and symlink escapes rejected. That folder is iCloud-synced on purpose: a file you ask for from your phone lands in the Files app.

Install and build

The Xcode project is generated from project.yml and deliberately not checked in, so the build starts with XcodeGen. Regenerate it whenever the file set changes. 

brew install xcodegen
git clone https://github.com/flx/FMail.git
cd FMail
xcodegen generate
xcodebuild -project FMail.xcodeproj -scheme FMail -configuration Debug build

Or open the generated FMail.xcodeproj and hit Run. Building needs Xcode 16 or later for Swift 6 language mode; it is developed and tested on Xcode 26. Run it once and look for the envelope in the menu bar — there is no window and no Dock icon.

Two permissions are needed. Full Disk Access, so FMail can read ~/Library/Mail — until it is granted, the dropdown shows a “Grant Full Disk Access…” item that opens the right System Settings pane. And Automation for Mail.app, which is what marking read or unread and Reply / Forward drive.
